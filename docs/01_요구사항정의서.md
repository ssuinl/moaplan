# 1. 요구사항 정의서 — 모아플랜

## 1.1 도메인과 선택 근거

**도메인:** 개인 목표 저축 계획 (예금·적금 조합 플래너)

| 확인 항목 | 내용 |
|---|---|
| 외부 API 3종 | 금감원 금융상품 한눈에(예금·적금 상품, 기간별 금리, 한도, 가입 제한, 우대 조건) · 한국은행 ECOS(소비자물가지수 → 물가상승률 계산, 기준금리) · 카카오 로컬(은행 영업점 이름·주소·링크) |
| 출처와 이용 조건 | README 「사용한 외부 API의 출처와 이용 조건」 참고 |
| 제약을 비교해야 답할 수 있는 요청 (3개 이상) | ① "1년 안에 1000만 원, 월 90만 원까지" → 세후 수령액 ≥ 목표, 필요 월 납입 ≤ 예산 ② "목돈 500만 원 + 매달 50만 원으로 6개월 뒤 1000만 원" → 예금 + 적금 조합 판단 ③ "2년에 1200만 원, 월 50만 원까지, 강남 근처" → 상품 월 한도와 영업점 ④ 이미 캘린더에 납입이 잡혀 있을 때 남은 예산으로 판단 |
| 저장·관리할 결과물 | 저축 계획 (제목, 목표, 상품, 시작일, 만기일, 매월 납입일, 월 납입액, 목돈, 세후 예상액, 생성 일시) |
| 위험 도메인 여부 | 금융 → 해당. 면책 문구: "이 결과는 금융감독원 공시 금리로 계산한 예상치이며 실제 수령액은 은행 계산 방식·가입 시점에 따라 달라질 수 있습니다. 금융 전문가의 상담이나 특정 상품 가입 권유를 대신하지 않습니다." |

**Tool 없이 LLM만으로 답하면 무엇이 틀리나 (대표 요청별 한 줄)**

| 요청 | 틀리는 것 |
|---|---|
| 1년 1000만 원, 월 90만 원 | 오늘 공시된 상품별 기본금리를 모르기 때문에 세후 수령액과 필요 월 납입을 지어냅니다 |
| 목돈 + 매달 조합 | 예금과 적금의 기간별 금리 차이, 단리·복리 구분을 모릅니다 |
| 월 한도가 있는 상품 | 상품별 월 납입 한도(max_limit)를 몰라서 가입할 수 없는 금액을 추천합니다 |
| 실질 수익률 | 최근 물가상승률을 모릅니다(ECOS 지수로 계산해야 함) |
| 영업점 | 실제 지점 이름과 주소를 지어냅니다 |

## 1.2 서비스 시나리오와 조건 분류

| 조건 유형 | 슬롯 | 예 |
|---|---|---|
| 기준 조건 | 목표 금액, 기간(개월) | 1000만 원, 12개월 |
| 선호 조건 | 상품 선호(예금/적금), 저축은행 허용, 영업점 지역 | 적금만, 저축은행 괜찮음, 강남 |
| 제약 조건 | 월 납입 상한, 지금 가진 목돈 | 월 90만 원, 목돈 300만 원 |

| 요청 유형 | Tool 순서 |
|---|---|
| 계획 수립 (plan) | 후보 조회(적금/예금 × 권역) → 상위 4개 상세 → 물가·기준금리 → 기존 일정 → [판정] → (지역이 있으면) 영업점 |
| 사실 조회 (fact) | 물가·기준금리 → 12개월 적금 상위 금리 |
| 제도 질문 (knowledge) | RAG 검색 |
| 계획 저장 (save_plan) | Tool 없음. 사용자가 고른 추천안을 서버가 저장합니다 |
| 캘린더 등록 (calendar) | 일정 등록(plan_id) |
| 그 밖의 대화 (chitchat) | Tool 없음 |

- **재계획이 일어나는 요청:** "1년 안에 1000만 원, 월 82만 원까지". 은행권은 필요 월 납입이 83만 원이라 탈락하고, 저축은행 권역을 추가하면 통과합니다.
- **상한에 도달하는 요청:** "1년 안에 5000만 원, 월 100만 원까지". 재계획 3회 뒤 멈추고 조정 방안을 역산합니다.
- **되묻는 요청:** "월 50만 원 가능해"처럼 목표 금액이나 기간이 없으면 Tool을 부르기 전에 되묻습니다.
- **겹치는 결과물 처리:** 납입 기간이 겹치는 계획이 있으면 저장은 막지 않습니다. 대신 겹치는 계획 목록, 겹치는 기간의 합산 월 납입액, 같은 납입일 여부를 알립니다.

## 1.4 비기능 요구사항

| 번호 | 내용 | 구현 |
|---|---|---|
| NF3001 | API 키는 환경변수 | `.env` + `.gitignore`, 코드에 키 없음 |
| NF3002 | 화면에 키·오류 상세 비노출 | `scrub()`, 전역 예외 처리기, 상태 API는 설정 여부만 반환 |
| NF3003 | Tool 실패해도 서비스 유지 | `Tool.run` 안전망, 실행기에서 실패를 기록하고 계속, 그래프 예외 시 안내 응답 |
| NF3004 | 재계획 상한 | `REPLAN_CAP = 3` |
| NF3005 | 응답 시간 | 권역 목록 캐시(10분), 대화 내 결과 재사용, 평가 리포트에서 측정 |
| NF3006 | 모듈 분리 | frontend / backend, agent / tools / events 패키지 |
| NF3007 | 출처·이용 조건 | README 표, RAG 문서 머리말 |

## 1.5 기획 검증 결과

| 검증 | 결과 | 설계 변경 |
|---|---|---|
| 외부 API 3종 호출 | `scripts/check_apis.py`로 확인 → `docs/evaluation/api_check.md` | — |
| 실제 응답 ↔ Tool 출력 대조 | 금감원 응답은 baseList(상품)와 optionList(기간별 금리)가 `fin_co_no + fin_prdt_cd`로 연결됩니다 | 상세 Tool이 목록 응답을 재사용하도록 설계했습니다(같은 목록은 캐시). 금감원 API에 단건 상세 조회가 따로 없기 때문입니다 |
| 비어 있는 값 | `max_limit`가 null이면 한도 없음입니다. 기간 옵션이 없으면 `NO_RATE` 입니다 | 0으로 채우지 않고 None 또는 판단 보류로 둡니다 |
| 공시 기간 | 저축 기간이 1·3·6·12·24·36개월뿐입니다 | 10개월처럼 공시 기간이 아니면 그 안에 끝나는 기간으로 계산하고 남는 개월을 응답에 밝힙니다 |
| 영업점 검색 | 공시 회사명에 '주식회사'가 붙으면 카카오 검색이 실패합니다 | Worker(F3021)의 LLM 인자 수정 사례로 사용했습니다 |
| 물가 | ECOS는 지수만 제공합니다 | 전년동월대비 상승률을 지수로 직접 계산하고 계산식을 응답에 보여 줍니다 |
| LLM 연결 · Tool 선택 | `check_apis.py`가 Tool 명세를 넘겼을 때 LLM이 Tool을 고르는지 확인합니다 | — |
| 설계 시험 | S1~S8 시나리오를 실행 단계 순서대로 따라가 봤습니다 (`docs/evaluation/results.md`) | 재계획 전략 '다음 순위 상품'을 반복 가능하게 바꿨습니다. 처음엔 1회만 가능해서 상한 3회가 의미가 없었기 때문입니다 |
