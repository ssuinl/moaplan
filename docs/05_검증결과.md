# 5. 검증 결과

검증은 네 갈래로 했습니다.
1. **자동 테스트** — `backend/tests` 56개. 4장의 확인 항목을 그대로 코드로 옮겼고, 키 없이 연습 데이터로 실행합니다.
2. **체크리스트 코드 확인** — `python -m scripts.check --fake` (또는 키를 넣고 `python -m scripts.check`). 3일차 방식대로 항목마다 **통과 · 실패 · 미확인** 으로 남기고, 실행하지 못한 항목은 통과로 적지 않습니다. 연습 데이터 기준 통과 14 · 실패 0 · 미확인 0. 처음 돌렸을 때 실패 2건(카카오 인증 헤더 값이 가려지지 않음, 규칙 LLM 이 '돈 좀 모으고 싶어'를 인사로 분류)을 찾아 고쳤습니다.
3. **대표 시나리오 평가** — 실제 API · GMS 로 시나리오 9개를 3가지 구조로 실행해 지표를 비교합니다 → [evaluation/results.md](evaluation/results.md). 키 없이 재현하는 연습 데이터 판은 `python -m scripts.evaluate --fake` → [evaluation/fake/results.md](evaluation/fake/results.md) (고장 주입 시험 포함)
4. **실제 API 확인** — `python -m scripts.check_apis` → [evaluation/api_check.md](evaluation/api_check.md)

> 실제 키로 돌린 결과는 `docs/evaluation/`, 화면 캡처는 `docs/screenshots/`에 있습니다 (목록은 4.9).

### 기대와 실제의 차이 · 수정 기록

| 발견 | 원인 | 수정 |
|---|---|---|
| 상한 3회가 실제로 걸리지 않음 | '다음 순위 상품' 전략이 1회만 가능했음 | 받은 목록에 남은 상품이 있는 한 반복하도록 변경 |
| 재계획 결과가 State에서 사라짐 | LangGraph State에 선언하지 않은 키(search_task_ids)는 버려짐 | State에 키를 선언 |
| 역할 분리 모드에서 같은 이상으로 재계획이 반복됨 | 검증 때마다 누적된 징후를 새것으로 판단 | 이미 보고된 징후를 기억하고 새 징후에만 반응 |
| 이미 잡힌 납입이 예산을 넘을 때 "목표를 0원으로 낮추기"라는 이상한 안내 | 조정 방안 계산이 음수 예산을 고려하지 않음 | "월 예산을 ○원으로 늘리기(기존 + 새 계획)" 문구로 변경 |
